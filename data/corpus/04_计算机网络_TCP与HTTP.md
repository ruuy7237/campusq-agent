# 计算机网络 · TCP 与 HTTP

## TCP 三次握手
客户端发送 SYN，服务端回复 SYN+ACK，客户端再发送 ACK。三次而非两次的原因是：两次握手无法让服务端确认客户端的接收能力，且历史上重复的 SYN 会导致服务端建立无效连接。

## TCP 四次挥手
主动关闭方发送 FIN，被动方回复 ACK，待数据发送完毕后再发送 FIN，主动方回复 ACK 并进入 TIME_WAIT。TIME_WAIT 持续 2MSL，用于保证最后一个 ACK 能到达并让旧报文在网络中消亡。

## 可靠传输机制
TCP 通过序号与确认应答实现可靠传输，配合超时重传、快速重传与滑动窗口。流量控制由接收窗口调节，拥塞控制包括慢启动、拥塞避免、快重传与快恢复。

## HTTP 与 HTTPS
HTTP 是无状态的应用层协议，HTTP/1.1 支持长连接，HTTP/2 支持多路复用与头部压缩。HTTPS 在 HTTP 与 TCP 之间加入 TLS，提供加密、身份认证与完整性校验。

## 状态码
2xx 表示成功，3xx 表示重定向，4xx 表示客户端错误，5xx 表示服务端错误。301 为永久重定向，302 为临时重定向，304 表示资源未修改可复用缓存。

## 缓存控制
强缓存由 Cache-Control 的 max-age 控制，协商缓存使用 ETag 与 If-None-Match。合理设置缓存可显著降低带宽与首屏时间。
