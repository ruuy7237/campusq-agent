# CampusQ · 课程资料问答

把课程资料做成一个能问答的系统。学生问一个考点，它从课件里找依据、答出来、标出处；
资料里没有的直接说没有，不编。

## 能做什么

- **问考点**：输入问题，返回答案 + 来源章节 + 置信度 + 耗时
- **拒答**：问资料里没有的东西，明确告诉你"未找到"
- **生成复习计划**：输入考试日期和薄弱章节，按天排出复习安排

## 三步跑起来

1. 双击 **`启动.bat`**。第一次会自动建虚拟环境、装依赖，之后直接启动
2. 浏览器打开 <http://127.0.0.1:8011>
3.停止服务

想跑评测：双击 **`评测.bat`**，结果写到 `data/metrics.json`，同时打印在窗口里。

想换自己的课件：把 markdown 文件丢进 `data/corpus/`，重启 `启动.bat`，索引会自动重建。

## 实际跑一遍是什么样

问一个资料里有的：

```
问：TCP 为什么需要三次握手

答：TCP 需要三次握手，是因为两次握手无法让服务端确认客户端的接收能力，
    且历史上重复的 SYN 会导致服务端建立无效连接 [4]。三次握手过程为：
    客户端发送 SYN，服务端回复 SYN+ACK，客户端再发送 ACK [4]。

来源：《计算机网络 · TCP 与 HTTP》  置信度 0.71  耗时 834ms
```

问一个资料里没有的：

```
问：食堂几点开门

答：资料中未找到相关内容，建议换一种问法，或补充这门课的资料后再问。
   refused = true
```

## 内部流程

```
问题
 ├─ BM25 关键词召回 ─┐
 └─ 向量语义召回   ─┴─ RRF 融合 → 词面重排 → top4 分块
                                    │
                        覆盖率 = 问题里的词在最佳分块中出现的比例
                                    │
                   < 0.28 ──────────┴────────── ≥ 0.28
                     │                            │
                  直接拒答              拼上下文 → LLM 带引用作答
                                                   │
                                          没配 key 时走抽取式兜底
                                                   │
                                    返回 {答案, 出处[], 置信度, 延迟}
```

两个关键点：

- **覆盖率只算长度 ≥2 的词**。单字重合太多，"学校"和"学习"会互相命中，不限制的话语料外的问题拦不住。
- **0.28 不是拍的**。`eval/tune_gate.py` 在 0.20~0.40 之间扫了一遍，这一档 29 条可答题放行 26 条，
  6 条不可答题一条没放进去。

## 接口

```bash
curl -s -X POST http://127.0.0.1:8011/ask \
  -H 'Content-Type: application/json' \
  -d '{"question": "TCP 为什么需要三次握手"}'
```

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/ask` | `{"question": "...", "top_k": 4}` |
| POST | `/plan` | `{"exam_date": "2026-11-20", "weak_topics": ["事务"], "hours_per_day": 2}` |
| GET | `/health` | 索引块数、当前向量后端、是否接了模型 |

## 指标

29 条可答 + 6 条语料外：

| 指标 | 不配 key（抽取式） | 配 key（deepseek-chat） |
|---|---|---|
| 检索 hit@1 | 86.2% | 86.2% |
| 检索 hit@3 | 96.5% | 96.5% |
| 一次解决率 | 72.4% | **89.7%** |
| 拒答准确率 | 100% | 100% |
| p50 延迟 | 1.6 ms | 867 ms |
| 全量评测 token | 0 | 约 2.8 万 |

检索两层数字一样，说明上限是检索定的；生成层把一次解决率从 72.4% 拉到 89.7%，
代价是延迟从毫秒涨到 800ms 级。

## 已知问题

- 语料只有 6 篇、12 个块。换真实课件要重调 chunk 大小和拒答阈值，现在这组参数不一定合适；
- 标注集是自己写的，问法比真实学生规整；
- 覆盖率是词面统计，同义改写会被误拒。比如"咋连不上"和"连接失败"覆盖不上，会被当语料外问题；
- 复习计划是规则模板按日期倒推，没有个性化。

## 目录

```
启动.bat / 评测.bat      一键启动、一键评测
app/ingest.py           切分建索引
app/qa.py               检索 → 闸门 → 生成
app/planner.py          复习计划
app/server.py           HTTP 接口 + 单页界面
core/store.py           BM25 + 向量 + RRF
core/embed.py           向量化（默认 md5 哈希，可切 bge-m3）
core/llm.py             模型调用（DeepSeek / 通义 / 本地都行）
core/text.py            分词与切块
eval/run_eval.py        评测
eval/tune_gate.py       扫拒答阈值
eval/metrics.py         指标函数
data/corpus/            6 篇课程资料
data/golden.jsonl       35 条标注（29 可答 + 6 不可答）
data/metrics.json       评测输出
```
